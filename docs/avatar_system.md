# Modular Avatar System

The production catalog lives at `assets/avatar/manifest/avatar_catalog.json`. It is the JSON source of truth for Flutter. The legacy `manifest/flutter_avatar_catalog.json` now points to the new catalog and includes flattened avatar, item, and pet lists for compatibility.

Catalog counts:
- 110 avatars: 10 starter and 100 advanced
- 376 unlockable items across 10 worn/side-prop categories (272 base items + 104 Prism variants)
- 270 pet companions (90 lines x 3 evolution stages)
- 756 total catalog assets

Supported slots:
- Worn: `headwear`, `eyewear`, `face_accessory`, `ear_accessory`, `neck_accessory`, `chest_badge`, `jacket_or_top_overlay`, `back_or_aura`, `background_frame`
- Side: `side_left_1`, `side_left_2`, `side_right_1`, `side_right_2`

Side-slot assets are pets or floating props. They are independent layers around the avatar and must not require finger alignment. Legacy `hand_prop` assets are migrated to `floating_props` with side-slot metadata.

The pet selection contains 90 catalog-backed companion lines across common, uncommon, rare, epic, and legendary tiers, each with three evolution stages (270 pet assets). Each pet has a trimmed transparent PNG, side-slot placement targets, XP unlock cost (base stage) or evolve condition (stages 2-3), rarity, species, personality, animation hint, mirrored support metadata and an `evolution` object.

Pet evolution contract (`evolution_contract_version: pet_evolution_v1`):
- `evolution.line_id` groups the three stages; ids are `<line_id>_001`, `_002`, `_003`.
- `evolution.stage` is 1, 2 or 3 with `stage_name` Base, Shiny or Radiant.
- `evolution.base_id` always points at the `_001` pet; `evolution.next_id` points at the next stage or is `null` on stage 3.
- `evolution.requires_level` is 1, 5 or 10. Pets gain XP while equipped; when the equipped pet reaches the `requires_level` of its `next_id`, the app unlocks `next_id`.
- Evolved stages cost `xp_cost: 0`, are `default_unlocked: false` and use `unlock_condition: "evolve:<base_id>:level:<n>"`.
- Evolved stages inherit the base's rarity, placement, z_index, allowed slots and species. Shiny keeps the base `sprite_size`; Radiant records its own larger `sprite_size` because of the glow.
- Shiny and Radiant art is generated from the base PNG by `scripts/build_pet_evolutions.py` (hue rotation, sparkles, rarity-tinted glow and rim light); see `docs/art_prompts/pet_generation_prompt.md`.

Item variants:
- `item_301_*_prism` to `item_404_*_prism` are Prism recolours of every rare, epic and legendary headwear, ear, neck, floating-prop and background-frame item (jacket overlays are excluded).
- Each carries `variant_of: "<base item id>"`, the tags `prism` and `variant`, `default_unlocked: false`, rarity bumped one tier and 1.5x the base XP cost rounded to 50 and clamped to the rarity band. Placement, sprite size, slots and z_index are copied from the base.
- Generated by `scripts/build_item_variants.py`.

Face fit (`face_fit_v1`, schema 3.1.0):
- Avatars carry a measured `face_rig` (named face points + reference widths); head, face and ear items carry a `fit` (rig anchor, sprite anchor, width relative to a rig width, `behind`). See README_INTEGRATION.md for the render rule.
- Fit kinds: cap, visor, shade_visor, bucket, headband, hood (behind), beanie, mortarboard, laurel, crown, headphones (behind), glasses, monocle, mask, gaiter, mustache, eyebrows, nose_strip, cheeks, cheek_mark, earring (computed per sprite).
- Item ids are historical and often do not describe the art (`item_007_halo_ring` is a bucket hat); the kind in `data/item_fit.json` and the display name are what count.
- Inputs: `data/face_rigs.json`, `data/item_fit.json`; build with `scripts/build_face_fit.py`; review with `scripts/render_fit_sheets.py`.

Placement contract:
- `schema_version: 3.1.0`
- `placement_contract_version: target_box_v1` (unchanged since 2.1)
- `evolution_contract_version: pet_evolution_v1`
- `face_fit_contract_version: face_fit_v1` (head, face and ear items; target boxes remain the fallback)
- `canvas_size` remains the virtual 512x512 composition frame.
- Avatar PNGs stay 512x512.
- Item and pet PNGs are tightly trimmed sprites; their real PNG dimensions are recorded in `sprite_size`.
- Each asset has `placement.anchor`, `placement.target`, `placement.fit: contain`, and `placement.scale_basis: target_box`.
- Side assets also have `placement.targets_by_slot`, keyed by `side_left_1`, `side_left_2`, `side_right_1`, and `side_right_2`.

Render rule:
1. Sort by `z_index`.
2. Render the base avatar full-frame.
3. For each equipped non-avatar layer, use `placement.targets_by_slot[equippedSlot]` when present, otherwise `placement.target`.
4. Center the trimmed sprite at `(target.cx, target.cy)` in normalized 0..1 canvas space.
5. Fit the sprite inside `(target.w, target.h)` of the 512 frame using contain, preserving aspect ratio.

`scale` is kept for compatibility and is now defined as an optional multiplier on the target box. New renderers should use `target.w/h` as the primary size contract.

Add a new asset by creating a transparent PNG, tightly trimming it to its alpha bounds, placing it in the matching folder, and adding a manifest entry with all required fields. Keep `style_version` set to `teen_modular_v1`, set `allowed_slots`, provide `placement`, `sprite_size`, `scale`, and `z_index`.

Build scripts (all deterministic and idempotent):
- `scripts/build_pet_evolutions.py` regenerates the Shiny/Radiant pets and the `evolution` objects.
- `scripts/build_item_variants.py` regenerates the Prism items.
- `scripts/build_flutter_manifest.py` regenerates `manifest/flutter_avatar_catalog.json` and `manifest/flutter_pubspec_snippet.yaml`.
- `scripts/build_sprite_atlas.py` rebuilds sprite sheets; generated assets live on their own sheets (`items_prism`, `pets_shiny`, `pets_radiant`) so the base sheets stay unchanged.

Validation:

```bash
python3 scripts/validate_avatar_catalog.py
python3 scripts/qa_avatar_visuals.py
python3 -m unittest tests/test_avatar_catalog.py
flutter analyze
```

Flutter integration:
- Load `AvatarCatalog.load()` from `flutter_example/avatar_pack_catalog.dart`.
- Store equipped assets in `EquippedAvatarLoadout.equipped`.
- Render with `AvatarPreview(catalog: catalog, loadout: loadout)`.
- Do not hardcode unlockables in widgets; resolve assets by ID from the catalog.

Migration notes:
- Starter avatar IDs are preserved as `avatar_basic_*`, with `avatar_type: starter`.
- Advanced avatar IDs are preserved as `avatar_advanced_*`.
- Legacy `glasses` category is now `eyewear`.
- Legacy `badge` category is now `chest_badge`.
- Legacy `neckwear` category is now `neck_accessory`.
- Legacy `back_accessory` category is now `back_aura`.
- Legacy `hand_prop` category is now `floating_props` and uses side slots.
- A full path-level migration map is embedded in `avatar_catalog.json` under `migration_map`.
